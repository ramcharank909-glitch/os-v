Understand OS Process States & Airport Analogy
✈️ The Airport Traffic Control Analogy ▼

Operating System process management can be challenging to visualize. The Airport Traffic Control (ATC) analogy maps each concept directly to real-world aviation:

  • Process $\leftrightarrow$ Aircraft Flight: An active job requiring resources and CPU time.
  • Single CPU Core $\leftrightarrow$ Active Runway 09L: Strictly single-occupancy! Only one aircraft can use the runway at a time.
  • Short-Term Scheduler $\leftrightarrow$ ATC Tower: Decides which queued aircraft gets the runway next based on algorithm policies (FIFO, Round Robin).
  • Preemption $\leftrightarrow$ Time Slice Go-Around: In Round Robin, if an aircraft exceeds its allotted runway slot, it is cycled back to the taxiway queue.
  • I/O Device Wait $\leftrightarrow$ Holding Apron (Weather/Clearance): An aircraft waiting for weather clearance cannot use the runway; once cleared, it rejoins the taxiway queue.
🟣 1. New State (Arrival Airspace) ▼

What is the New state? A process is in the New state when it is being created by the Operating System (e.g. fork()). Memory is allocated and a Flight Control Block (PCB) is created.

Transition (New → Ready): Once the OS long-term scheduler admits the flight, it moves to the Ready state on the taxiway.

🔵 2. Ready State (Taxiway Alpha Queue) ▼

What is the Ready state? A process is in main memory (RAM) and has all resources except the CPU. It waits in the Ready Queue for the short-term CPU scheduler.

Transition (Ready → Running): When the CPU core (runway) is idle, the scheduler dispatches the first aircraft into the Running state.

🟢 3. Running State (Active Runway 09L) ▼

What is the Running state? The process instructions are actively executing on the CPU core. Only one process can occupy a single CPU core at any time.

Transitions from Running:

  • Running → Ready: Preemption! Time quantum expired.
  • Running → Waiting: The process requested I/O (e.g. weather clearance).
  • Running → Terminated: The process finished its execution bursts.
🟠 4. Waiting / Blocked State (Holding Apron) ▼

What is Waiting? The process cannot execute even if the CPU is 100% idle! It is waiting for an external event (I/O completion, weather clearance).

Transition (Waiting → Ready): When the event finishes, the process moves back to Ready. It does not jump directly to the CPU.

🔴 5. Terminated State (Departure Gates) ▼

What is Terminated? Execution completed. The Operating System reclaims memory and removes the PCB.

⚖️ Ready vs. Waiting: The Key Difference ▼

Ready: The process is capable of running immediately if given the CPU. It only lacks CPU time.

Waiting (Blocked): The process cannot run even if the CPU is idle, because it is waiting for an external event or I/O device.

Airport Traffic Control Presentation Script (2–3 Minutes)
Part 1: Introduction (30 seconds)
"Respected Professor and peers, today I am presenting the Airport Traffic Control OS Process State Simulator. In multiprogramming operating systems, processes dynamically transition through five fundamental states: New, Ready, Running, Waiting, and Terminated. To make these abstract concepts intuitive, our project introduces an interactive Airport Traffic Control metaphor where aircraft represent processes, the active runway represents the single CPU core, and the ATC Tower represents the OS scheduler."
👉 Action: Point to the Airport Scene, Runway 09L, and the 5-state process diagram.
Part 2: Live Demonstration (90 seconds)
"Let's observe our live demonstration with three flights under Round Robin CPU scheduling ($q=2$ ticks):

• At Tick 0, FL-101, FL-102, and FL-103 enter the airport airspace and taxi into the Ready Queue.
• The ATC Tower dispatches FL-101 onto Runway 09L (Ready → Running).
• After 2 ticks of runway acceleration, FL-101 encounters a weather check hold. It moves from Running → Waiting, immediately freeing the runway!
• The scheduler dispatches FL-102. When its 2-tick quantum expires, the OS preempts FL-102 back to the taxiway queue (Running → Ready).
• As FL-101's weather clearance completes, notice that it transitions from Waiting → Ready to rejoin the queue fairly.
• Finally, as flights complete their full burst, they take off into the Terminated departure corridor."
👉 Action: Click "Step" tick by tick or use the Manual ATC Dispatcher controls to demonstrate valid transitions.
Part 3: Key Takeaway & Conclusion (30 seconds)
"This simulation proves how the Operating System enforces mutual exclusion on the CPU, balances responsiveness through Round Robin time-slicing, and distinguishes between processes that are Ready versus Blocked in I/O. Thank you!"
👉 Action: Show the live Statistics Dashboard and Gantt Chart.
